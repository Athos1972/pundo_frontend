# Internationalisierung (I18n)

## Unterstützte Sprachen

| Code | Sprache | RTL |
|---|---|---|
| `en` | Englisch | Nein |
| `de` | Deutsch | Nein |
| `el` | Griechisch | Nein |
| `ru` | Russisch | Nein |
| `ar` | Arabisch | **Ja** |
| `he` | Hebräisch | **Ja** |

## Sprachauswahl

- URL: Customer-Pages tragen den Sprach-Prefix `/{lang}/…`; `src/proxy.ts` leitet Pfade ohne Prefix um und setzt den Request-Header `x-lang`
- Cookie: `app_lang` (1 Jahr, SameSite=Lax) — setzt der Proxy automatisch, ist also kein Signal für eine bewusste Wahl
- Server: `getLangServer()` aus `src/lib/lang.ts` — liest `x-lang`, sonst Cookie via `next/headers`
- Client: `getLangFromCookie()` aus `src/lib/lang.ts`
- Fallback: `DEFAULT_LANG` (`src/lib/lang.ts`)

### Sprach-Hinweis (LanguageHint, F6310)

`src/components/ui/LanguageHint.tsx` ersetzt seit 2026-10-14 das frühere Vollbild-Overlay `LanguagePickerOverlay`
(seit F6300 unerreichbar, weil `src/proxy.ts` `app_lang` bei jeder `/{lang}`-Antwort setzt; als Mobile-Interstitial zudem SEO-Risiko).

- Kleiner, nicht modaler Toast unten am Start-Rand („Sprache: Deutsch · Ändern“, über der `BottomTabBar`), eingebunden in `src/app/(customer)/[lang]/layout.tsx` → nur Customer-Seiten
- Nur clientseitig gerendert (`useSyncExternalStore`, Server-Snapshot = ausgeblendet) → nicht im SSR-HTML, kein CLS
- Signal für „bewusste Wahl“: Cookie `lang_hint_dismissed` (1 Jahr, `src/lib/lang-hint.ts`). Gesetzt beim Schließen (X), bei Sprachwahl im Hinweis und im Header-`LanguageSwitcher`
- Wartet, solange der Cookie-Consent-Banner offen ist (beide sitzen am unteren Rand)
- „Ändern“ klappt die 6 Sprachen in Eigenbezeichnung (`LANG_NATIVE_NAMES`) auf; Wahl → `router.push` auf `/{lang}/…`, Query-String bleibt erhalten
- Weicht die erste unterstützte Browsersprache (`detectSupportedBrowserLang()`) von der URL-Sprache ab, zeigt er sie als Vorschlag („Русский?“)
- Strings: `src/lib/i18n/language-hint.ts` (`tLanguageHint`)
- E2E: `e2e/language-hint.spec.ts`. Andere Specs brauchen keine Vorkehrung (ohne Consent-Cookie bleibt der Hinweis aus, und er blockiert keine Klicks); falls doch einmal nötig, Cookie `lang_hint_dismissed=1` setzen

## RTL-Behandlung

- `isRTL(lang)` → `true` für `ar`, `he`
- Es gibt kein Root-`src/app/layout.tsx`: jede Route-Group hat ein eigenes Layout mit `<html lang={lang} dir={…}>` (`src/app/(customer)/layout.tsx`, `(shop-admin)`, `(oauth)`; `(system-admin)` ist fest `en`/`ltr`)
- Tailwind: `rtl:` Modifier für spiegelbare Layouts (`rtl:text-right`, `rtl:flex-row-reverse`)
- **Niemals im Frontend raten** — `rtl`-Flag immer aus API-Response oder `src/lib/lang.ts` lesen

## UI-Strings hinzufügen

Die Strings liegen in Namespace-Dateien unter `src/lib/i18n/*.ts` (z. B. `common.ts`, `search.ts`, `shop.ts`, `shop-admin-*.ts`). `src/lib/translations.ts` ist nur ein Barrel, das sie zusammenführt und die Helper (`tCommon`, `tSearch`, …) re-exportiert.

1. Neuen Key im `en`-Block der passenden Namespace-Datei hinzufügen
2. Für alle anderen 5 Sprachen in derselben Datei übersetzen
3. `npm run lint:i18n` ausführen (`scripts/check-i18n-parity.ts`) — meldet fehlende/überzählige Keys je Sprache. Neue Namespace-Dateien dort registrieren.

```typescript
// src/lib/i18n/<namespace>.ts
const contactTranslations = {
  en: { my_new_key: 'My new string', /* ... */ },
  de: { my_new_key: 'Mein neuer Text', /* ... */ },
  // ... alle 6 Sprachen
} as const

export type ContactTranslations = typeof contactTranslations.en
export function tContact(lang: string): ContactTranslations { /* … */ }
```

## Dynamische Inhalte

Produktnamen, Kategorienamen und Shop-Adressen kommen übersetzt vom Backend — kein Frontend-Mapping nötig.  
Das Backend liest den `Accept-Language`-Header und liefert die passende Übersetzung.

## Translation-Key-Referenz

Alle Keys: die Namespace-Dateien in `src/lib/i18n/` (Typ je Namespace: `typeof <ns>Translations.en`). Die Keys unten liegen in `src/lib/i18n/common.ts` (`contact_shop` in `src/lib/i18n/shop.ts`).

Wichtige Keys:

| Key | Typ | Verwendung |
|---|---|---|
| `price_on_request` | `string` | Label für Angebote ohne Fixpreis |
| `price_free` | `string` | Label für kostenlose Angebote |
| `price_variable` | `string` | Label für variable Preise |
| `filter_price_only` | `string` | Filter-Chip auf Suche/Produktseite |
| `contact_shop` | `string` | CTA-Button bei `on_request`-Angeboten |
| `available` | `string` | Verfügbarkeits-Badge |
| `unavailable` | `string` | Nicht-verfügbar-Badge |
| `days_ago` | `(n: number) => string` | Relative Zeitangabe |
| `subcategories` | `(n: number) => string` | Kategorie-Zähler |
